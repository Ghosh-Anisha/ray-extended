
# Phase U3 (Ask RAY, Rules, coach marks)

- **Answers are code, not a model.** Ask RAY answers from the database in `src/ask/answer.ts`, so every number is computed and cited, it works the same in replay, live and record mode, and nothing a customer wrote can steer it. Spec asked for "replay fixtures for the starter chips"; instead the starter chips are pinned by tests in `src/ask/ask.test.ts` that check the cited numbers against `merchantStats` and the banned words. Alternative: add `fixtures/ai/ask/` through the converse job. Not done because it would put model-written numbers in front of the merchant for no gain.
- **Rule requests are parsed by regex, never executed.** `parseRuleRequest` makes a plan; Approve rule is the only thing that saves it, and the route re-validates the plan with zod. Rules are stored in the existing `playbook_rules` rows with the same `rule_json` shapes the flows already read (refund duplicate, capture, place_call with `min_value`, chargeback contest lane). "Always bring me cases above ₹X" sets the existing approval limit. Tone and sign-off write the existing setting rows for every moment. No flow or guard changed.
- **"Under ₹500" saves ₹499.** The seeded suggested rule already uses a max of 49,900 paise, so approving it from chat and from the Rules page is the same rule. Editing the amount replaces the rule rather than adding a second one.
- **Capability list lives in `src/ask/capabilities.ts`.** Moments are On when RAY handled a case of that kind in the last 30 days, else Try it; the five designs from section 13 that have no screen yet are Coming soon. The Home session can read the same function.
- **One conversation, two places.** The side panel and `/ask` share one thread (`AskProvider` in the shell). A case page scopes the panel to that case; a case is only answered for its own merchant.
- **Nudge on Ask and Rules names the shortest suggestion.** Chargeback lane rules have long wording, so the Rules page shows their short name ("Contest without asking") with the full wording underneath.
- **Settings reuse.** The old `src/ui/merchant/playbook.tsx` is no longer used by a page (its settings moved into the collapsed Settings section of `rules.tsx`). I left the file and its tests alone.
- **Coach marks queue.** Only one pop-up shows at a time, in the order screens registered, so the ✦ RAY tip and a page's tips never overlap. "Show me around" in the account menu clears them and replays. `CoachPopover` is exported for the guided demo.
